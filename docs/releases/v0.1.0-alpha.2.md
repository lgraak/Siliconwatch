# SiliconWatch v0.1.0-alpha.2

## New features and fixes

The CLI and foreground daemon can read NVIDIA telemetry through the driver's optional NVML library. The native sensor table and Device Details display temperature, utilization, VRAM, graphics and memory clocks, performance state, fan speed and power where supported. Unsupported readings carry an unavailable status. UUID and PCI evidence keep channel identities stable across enumeration changes. The provider closes each NVML session and avoids a driver descriptor leak during repeated acquisition.

The Slint Monitoring tab saves requested sampling and freshness intervals in TOML and shows the daemon’s effective settings. Restart the foreground daemon with the displayed command to apply pending timing requests. The GUI applies the saved API timeout to new requests. Detection of an occupied socket identifies the existing endpoint and preserves the running daemon.

## API and settings compatibility

API v1 retains its two read-only methods. Strict `get_info` validators need the updated schema for the optional timing metadata. NVML v2 reports reserved memory directly. Legacy used and total memory have distinct identities and session statistics.

**Back up your settings before upgrading.** Close the GUI and copy `${XDG_CONFIG_HOME:-$HOME/.config}/siliconwatch/config.toml` if it exists. Alpha 2 loads older profiles with defaults. Alpha 1 rejects profiles saved with the new `[monitoring]` section. Restore your saved Alpha 1 profile if you downgrade.

## Installation and startup

Select the x86-64 package built for your distribution. Verify downloaded package bytes against the corresponding entry in `SHA256SUMS`. Use the native package manager for installation or upgrade.

```sh
# Debian or Ubuntu
sudo apt install ./siliconwatch-0.1.0-alpha.2-linux-amd64.deb

# Fedora 44
sudo dnf install ./siliconwatch-0.1.0-alpha.2-linux-x86_64.rpm

# Compatible Arch rolling snapshot
sudo pacman -U ./siliconwatch-0.1.0-alpha.2-linux-x86_64.pkg.tar.zst
```

Restart running Alpha 1 processes after upgrading. As your normal user, start `siliconwatch daemon --interval-ms 1000 --stale-after-ms 3000 --local-api` in one terminal and `siliconwatch-gui` in another. Installation does not start a service or install drivers. The packaged CLI and GUI use the current user's peer-verified read-only API. The accompanying source archive includes the project, the Rust 1.85 fontdue patch and locked dependency sources for offline Cargo builds.

## Qualification and limitations

Milestone 011 was accepted on a physical Quadro P620 with NVIDIA driver 580.196.07. Temperature, utilization, clocks, VRAM and performance state matched the neighboring `nvidia-smi` observation to its display precision. The P620 returned unavailable for fan speed and power. Over 100 warm acquisitions the descriptor count remained stable, median acquisition took 6.64 ms and p95 took 6.84 ms. Reordering two GPUs, device loss and driver failure were exercised with fixtures. Physical coverage extends to one GPU and driver.

The accepted workspace ran 287 passing tests and two opt-in desktop-bus tests, which also passed separately. The candidate’s build and verification reports identify the distribution images, package checks and fixture tests for its exact bytes. Desktop qualification depends on the distribution and session. Clean CachyOS installation and real desktop interaction require their own evidence. Slow ACPI acquisition can delay publication of all readings. A process restart loads a replacement NVML library. Live daemon configuration, AMD GPU telemetry and provider isolation are future work.
