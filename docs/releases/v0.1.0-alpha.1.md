SiliconWatch's first experimental alpha brings a native Slint desktop GUI together with Rust command-line tools for local, read-only Linux hardware monitoring. It is intended for external testing and feedback. It is not production-ready or suitable for safety-critical hardware protection.

## What is included

- **OLED Black by default**, with Dark and Light themes, adjustable fonts, row density and columns.
- A grouped Sensors table with **Current, Minimum, Maximum and Average**. Statistics cover distinct valid observations received during the GUI session; they are not persistent or time-weighted history.
- **Device Details** with readings, raw values, units, source identity evidence, diagnostics and observation timing. Unsupported, stale and unavailable values remain explicit.
- CLI table/JSON output, bounded sampling and a **manually started foreground daemon**. The GUI reads the daemon's cache through the current user's local Unix-socket API; GUI refresh does not request another hardware scan.
- StatusNotifier-compatible tray integration and **optional Minimize to Tray**, off by default. Quit exits the GUI while leaving the separately started daemon running.
- Current-user TOML settings and reviewed appearance/layout import/export. Imports and exports are GUI actions under **Settings → Import, Export & Recovery**; enter an absolute local path and review the confirmation. Optional device-group selectors can reveal source topology, so leave them out unless needed.

Installation does not start background monitoring, install/enable a service, load kernel modules, change API permissions or modify hardware. There are no fan controls, alarms, protective actions, remote access or write API methods.

## Install and run

Download the package for your distribution and verify its checksum against `SHA256SUMS`. From the download directory, use the appropriate native package manager:

```sh
# Debian / Ubuntu
sudo apt install ./siliconwatch-0.1.0-alpha.1-linux-amd64.deb

# Fedora 44
sudo dnf install ./siliconwatch-0.1.0-alpha.1-linux-x86_64.rpm

# Arch Linux
sudo pacman -U ./siliconwatch-0.1.0-alpha.1-linux-x86_64.pkg.tar.zst
```

Run the application as your ordinary desktop user. Start the daemon manually in one terminal:

```sh
siliconwatch daemon --interval-ms 1000 --stale-after-ms 3000 --local-api
```

Leave it running and launch the GUI from the application menu or another terminal:

```sh
siliconwatch-gui
```

The GUI connects to `$XDG_RUNTIME_DIR/siliconwatch/api.sock`. If the daemon is absent, it shows a disconnected state; start the daemon, then choose **Reconnect**. Do not run either application with `sudo` or loosen runtime/socket permissions. Ctrl-C in the daemon terminal requests cooperative shutdown and removes its owned endpoint when shutdown completes.

For one-shot CLI output, use `siliconwatch sensors` or `siliconwatch sensors --json`. The CLI and foreground daemon share one executable; no duplicate daemon binary is installed.

Select a sensor and choose **Open Details**, double-click it or press Enter. Settings contains the three themes and import/export controls. **Minimize to Tray** requires a usable desktop tray host; without one, closing the last window exits. If a usable host disappears while Sensors is hidden, the application restores Sensors. Compositor focus and tray presentation can vary.

User preferences are stored in `$XDG_CONFIG_HOME/siliconwatch/config.toml`, falling back to `~/.config/siliconwatch/config.toml`. Package removal preserves preferences and exported profiles. First quit the GUI and stop any daemon you started, then use `apt remove siliconwatch`, `dnf remove siliconwatch` or `pacman -R siliconwatch` with the normal package-manager privileges. Full installation and GUI documentation is included with the package under `/usr/share/doc/siliconwatch/`.

## Tested environments and limits

All three packages were built from the intended source with **Rust 1.85.0**, Slint 1.13.1 and the approved six-conversion fontdue 0.9.5 patch, in separate target-distribution environments.

| Package | Build and isolated installation targets | Highest GUI GLIBC reference |
|---|---|---:|
| Debian | Built on Debian 12; installation/removal tested on Debian **12.15** and Ubuntu **24.04.5 LTS** | 2.35 |
| Fedora | Built and installed/removed on Fedora **44** | 2.43 |
| Arch | Built and installed/removed using official Arch rolling image **20261108.0.623074** | 2.43 |

The package tests verified dependency resolution, installed CLI/JSON against synthetic sensor fixtures, the manually started daemon, read-only API responses and permissions, clean shutdown, package removal and preservation of user preferences. Virtual display tests exercised the recorded software graphics environments; they do not establish an actual desktop session on each distribution.

The final production GUI binaries from all three packages passed launch/tray/connection/quit checks on the available **CachyOS KDE Wayland host**, using both Wayland and XWayland: six final cases passed. This is execution of the verified binaries on that host, not native CachyOS package-manager installation qualification. Linux Mint, CachyOS and EndeavourOS package installation remain untested. Older Fedora versions and Fedora 45 are unqualified.

**Unresolved Wayland qualification failures remain:** the fresh instrumented full-workflow probe timed out waiting for its initial snapshot at 60 seconds, and the instrumented lifecycle probe did so at 45 seconds. The instrumented matrix passed 4/6 cases: XWayland 3/3 and Wayland 1/3, with two additional successful XWayland profile restarts. The Wayland failures and prior screenshot/visibility timeout evidence are retained; their cause is not established. Passing production launches or a different successful test do not prove those failures resolved.

Human keyboard/screen-reader qualification, physical tray/menu interaction, GNOME, a separate Xorg desktop and mixed-monitor behavior remain open. Native KDE testing does not establish all KDE versions or compositor configurations. Performance/resource targets, physical sensor calibration and universal binary portability are not claimed. Physical measurement age can be unknown even when a cached observation was recently assessed.

## Hardware coverage

Readings depend on sensors exposed by supported Linux drivers. On a tested GMKtec EVO-X1 with an IT8613E monitoring chip, the existing Linux `it87` driver exposed two fan channels and SiliconWatch displayed their RPM without application changes. That example does not establish universal motherboard/Super I/O support, independent calibration, physical CPU/System fan mapping or future kernel/reboot compatibility.

SiliconWatch does not install or force monitoring drivers, bypass ACPI protections or change fan/PWM settings. Missing sensors may reflect driver or firmware coverage rather than a GUI permission problem.
